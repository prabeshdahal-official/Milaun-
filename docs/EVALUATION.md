# Evaluation methodology

> All figures are regenerated by `python benchmarks/evaluate.py`, which writes
> `benchmarks/results/RESULTS.md` and `eval.json`. Read those files for the current numbers;
> this document explains how they are produced and what they do not prove.

## Dataset

**Provenance.** `benchmarks/data/seed_names.csv` is a hand-written list of 100 common Nepali
given-name/surname combinations, each with a Devanagari and a Latin spelling. It contains no
real people and no scraped records. Variants are generated from that seed list by
`benchmarks/synth.py` with a fixed seed, so the dataset is reproducible without committing
personal data or large files.

**Why synthetic.** No openly licensed corpus of labelled Nepali name variants exists, and
scraping patient or beneficiary records would be unethical and probably illegal.

**Operations.** Each variant applies one or two documented transformations:

| Family | Operations |
|---|---|
| `dev` (train/calibrate/evaluate) | aspiration swap, retroflex↔dental, vowel length, nasal mark, final schwa, Latin aspiration, vowel digraph, `v`/`b`/`w`, `sh`/`s`, consonant doubling, final `y`/`i` |
| structural | token swap, middle-name drop, middle initial |
| `hard` (held out entirely) | nukta, halant removal, sibilant swap, character deletion/substitution |

**Negatives.** Four kinds, all required for a realistic precision estimate:

1. random other identities;
2. same surname, given name one *consonant class* apart (`Prabesh` vs `Prabin` territory);
3. same given name, different surname (`Sita Sharma` vs `Sita Karki`);
4. mixed-script pairs in the same proportion as positives.

Vowel-only edits are deliberately **not** used as different-person negatives: `Prabesh` vs
`Pribesh` is far more likely a typo of one person, and labelling it negative would punish
correct behaviour.

**Splits.** Whole identities, not pairs, are assigned to train/calibrate/test (60/20/20) so no
person leaks across splits. `hard` operations are test-only.

## Metrics

- **Precision / recall / F1 at the fixed auto threshold (0.90)** — the operating point a user
  actually experiences.
- **PR-AUC (average precision)** with tied scores consumed as one operating point. Breaking
  ties by rank silently rewarded input order for discrete comparators; this was a real bug
  found and fixed during development.
- **ROC-AUC**, tie-aware.
- **ECE (10 equal-width bins)** and **Brier score** for probability quality.
- **Blocking pair completeness** — share of true duplicate pairs surviving candidate generation.
- **Cluster-level pairwise precision/recall and cluster purity** on a 180-record registry.
- **Latency** (pairs/second on one core) and **peak memory** via `tracemalloc`.

## Baselines

`exact`, normalised Levenshtein, Jaro-Winkler, classic Soundex, and a Latin-only phonetic key.
All baselines receive the same Devanagari→Latin transliteration the model uses, which is
generous: a real deployment of those tools would have to transliterate by hand first. Each is
tuned on the calibration split (best F1) and then frozen.

## Threats to validity

1. **Generator bias.** Positives are produced by transformations the encoder was designed to
   absorb. High recall partly measures that design, not general robustness. The `hard` split is
   the only partially independent check, and it is still synthetic.
2. **Label ambiguity.** One-consonant differences are treated as different people. In a real
   registry some of those would be typos of the same person, so measured precision is a
   conservative estimate in that region.
3. **No homonyms in the benchmark.** Identical names belonging to different people are excluded
   from the metrics because no name-only matcher can separate them. The `homonym_probe` in
   `eval.json` records the floor explicitly.
4. **Small calibration split** (~300 pairs), so the calibration curve itself is noisy.
5. **Single annotator.** The seed list and the operation set reflect one Nepali speaker's
   judgement; regional and caste-specific naming conventions are under-represented.

## Reproducing

```bash
python benchmarks/train.py      # fits weights + Platt curve, writes src/milaun/data/*.json
python benchmarks/evaluate.py   # writes benchmarks/results/{eval.json,RESULTS.md}
pytest                          # 127 tests, including benchmark-integrity checks
```

`tests/test_benchmark.py` asserts determinism, split isolation, absence of self-pairs, and the
tie-aware PR-AUC behaviour, so the harness cannot silently drift.

## What would change the conclusions

A hand-labelled set of a few thousand real record pairs from one clinic or cooperative,
annotated by two independent reviewers with an agreement statistic. Until then, treat the
numbers as evidence of engineering care, not of field accuracy.
